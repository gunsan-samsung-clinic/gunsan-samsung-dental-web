# 군산 삼성치과 — 고객 전용 페이지 & 어드민 관리 설계

## 배경

현재 `gunsan-samsung-dental-web`은 GitHub Pages로 배포된 순수 HTML/CSS/JS + Firebase Firestore 사이트로, 병원소식/이벤트/후기 등을 보여주는 완전 공개 홍보 페이지다. 로그인이나 관리자 화면은 없고, 콘텐츠는 Firebase 콘솔에서 직접 입력하는 것으로 추정된다.

이번 작업의 목표는 두 가지다.
1. **기존 고객 전용 콘텐츠**(혜택/쿠폰, 치료 후 관리 안내, 상담 신청)를 담은 별도 페이지를 만든다.
2. 병원 직원이 개발 지식 없이 콘텐츠를 직접 관리할 수 있는 **어드민 페이지**를 만든다.

이 사이트는 군산 삼성치과에 판매(계약)하는 제품이며, 계약서(`계약서 추가 사항.txt`, 저장소에는 미포함)상 "관리자 페이지 구축"은 기본 "평생 관리" 범위를 벗어난 별도 협의 항목이다. 다른 병원에 재판매할 계획은 현재는 없고(YAGNI), 군산 삼성치과 전용으로 만든다.

## 기존 상태 조사에서 확인한 사실

- 배포된 공개 사이트: 1분 치아상식, 릴스, 이벤트, 공지사항, 질의문답, 후기 6개 섹션. 예약 기능·연락처 없음.
- 저장소 구성: `index.html`, `style.css`, `app.js`, `firebase.js`. 프레임워크 없음, Firestore(`events`, `news`, `reviews` 컬렉션) 사용.
- `app.js`는 인증 없이 Firestore 데이터를 그대로 읽어서 `innerHTML`로 렌더링.
- 로컬(바탕화면)에 있던 별도 작업본은 `index.html` 안에 어드민 로그인 + 이벤트/공지/후기/메모 관리 폼이 통째로 포함된 초기 프로토타입이었으나, GitHub 쪽이 더 최근까지 다듬어진 버전이라 **GitHub을 기준으로 하고 로컬 프로토타입은 참고만 하기로 결정**했다 (코드는 재사용하지 않음, `Desktop/gunsan-samsung-dental-web_old_local_backup`에 백업 보관).
- 어드민 로그인용 Firebase Auth 계정은 이미 생성되어 있음 (이메일/비밀번호 방식).

## 요구사항 정리

- 고객 전용 콘텐츠 범위: **혜택/쿠폰 안내** + **치료 후 관리 안내(정적 콘텐츠, 자동 알림 발송 없음)** + **상담 신청 폼**.
- 접근 방식: 로그인 없이 접근 가능한 별도 URL. 검색엔진 노출은 막는다(`noindex`). 공개 홈페이지(`index.html`)에는 이 페이지로 가는 링크를 넣지 않고, 병원이 내원 고객에게 URL/QR코드로 직접 안내한다. (가벼운 접근 제한이며, 나중에 완전 공개 또는 로그인 방식으로 바꾸는 것도 쉽게 가능하다.)
- 어드민 페이지: 기존 Firebase Auth 계정으로 로그인. 로그인 후 이벤트/공지/후기(기존) + 혜택·쿠폰/사후관리 안내(신규)를 추가·수정·삭제하고, 상담 신청 목록을 확인.
- 상담 신청: 이름/연락처/문의내용을 입력하면 Firestore에 저장되고, 어드민 화면에서만 확인 가능 (기존 구조와 통일, 이메일 등 외부 서비스 추가 연동 없음).
- 판매 대상은 군산 삼성치과 1곳. 다른 병원 대상 재사용성은 고려하지 않는다.
- 병원 직원이 개발 지식 없이 관리할 수 있도록 (1) 어드민 UI를 한글 라벨/명확한 버튼으로 직관적으로 만들고, (2) 별도 사용 설명서 문서를 제공한다.

## 기술 접근 방식

기존 vanilla JS + Firebase 구조를 그대로 확장한다 (빌드 도구/프레임워크/로우코드 어드민 툴 도입 안 함). 이유:
- 지금 배포 방식(GitHub Pages, 빌드 없음)을 그대로 유지할 수 있다.
- "미니멀한 제품"이라는 목표와 맞고, 병원 측 유지보수 부담이 없다.
- 외부 서비스 종속이 생기지 않는다 (계약상 "평생 관리"는 서버가 살아있고 오류를 확인해주는 수준이므로, 관리 부담을 늘리는 선택은 피한다).

## 아키텍처 & 파일 구조

```
gunsan-samsung-dental-web/
├── index.html          (기존, 유지 — 공개 홍보 페이지)
├── customer.html        (신규 — 고객 전용 페이지, robots noindex)
├── admin.html            (신규 — 어드민 로그인 + 관리 화면)
├── app.js               (기존 6개 섹션 로직, 유지)
├── customer.js          (신규 — 고객 전용 콘텐츠 로드 + 상담 폼 제출)
├── admin.js              (신규 — 어드민 CRUD 로직 + Firebase Auth)
├── firebase.js           (기존 — Firebase 초기화, 공용으로 계속 사용)
├── style.css             (기존 CSS 확장)
├── firestore.rules       (신규 — Firestore 보안 규칙을 코드로 관리)
└── docs/사용설명서.md   (신규 — 병원 직원용 관리 가이드)
```

- `index.html`: 변경 없음, 지금처럼 검색 노출.
- `customer.html`: 새 URL. 로그인 없음, `<meta name="robots" content="noindex, nofollow">` 적용.
- `admin.html`: Firebase Auth 로그인 후에만 관리 화면 노출.

## Firestore 데이터 모델

**기존 컬렉션 (유지, 공개 읽기 / 어드민만 쓰기)**: `events`, `news`, `reviews`

**신규 컬렉션**

| 컬렉션 | 용도 | 주요 필드 |
|---|---|---|
| `benefits` | 고객 전용 혜택/쿠폰/이벤트 | `title`, `description`, `imageUrl?`, `startDate`, `endDate`, `active` |
| `aftercare` | 시술별 사후관리 안내 | `procedureName`, `content`, `order` |
| `consultations` | 상담 신청 접수 | `name`, `phone`, `message`, `createdAt`, `status`(`신규`/`확인완료`) |

## 보안 규칙 방향

- `events`, `news`, `reviews`, `benefits`, `aftercare`: 누구나 읽기 가능, 쓰기는 `request.auth != null`(로그인한 어드민)만.
- `consultations`: 누구나 **생성(create)만** 가능 (정해진 필드 형식 검증), **읽기/수정/삭제는 어드민만**. 다른 고객이 남의 상담 내용을 볼 수 없도록 한다.
- 규칙은 Firebase 콘솔에 수동 입력하지 않고 `firestore.rules` 파일로 저장소에 코드로 관리한다.

## 어드민 페이지(`admin.html`) UX

- 로그인 화면: 이메일/비밀번호 → Firebase Auth 로그인. 미로그인 시 관리 화면 비노출.
- 로그인 후 단일 화면, 메뉴(탭)로 구분:

| 메뉴 | 기능 |
|---|---|
| 이벤트 | 목록, 추가/수정/삭제 |
| 공지사항 | 목록, 추가/수정/삭제 |
| 후기 | 목록, 추가/삭제 |
| 혜택·쿠폰 (신규) | 추가/수정/삭제, 시작~종료일 설정, 보이기/숨기기 토글 |
| 사후관리 안내 (신규) | 시술명별 안내 글 추가/수정/삭제 |
| 상담 신청함 (신규) | 신청 목록 확인, "확인완료" 표시, 삭제 |

- 각 메뉴는 "목록 + 입력 폼" 한 화면, 탭 전환만 (페이지 이동 없음).
- 모든 라벨/버튼은 한글, 전문용어 없이 직관적으로. 삭제는 확인창으로 실수 방지.

## 고객 전용 페이지(`customer.html`) UX

레이아웃은 스크롤 한 번이면 다 보이는 정도로 미니멀하게 구성한다.

1. 상단 — 병원 로고 + 짧은 인사말.
2. **혜택·쿠폰** — 현재 진행 중(active, 기간 내)인 항목만 카드로 표시.
3. **사후관리 안내** — 시술명 목록, 클릭 시 안내 내용이 펼쳐지는 아코디언.
4. **상담 신청** — 이름/연락처/문의내용 입력 폼. 제출 시 "접수되었습니다, 병원에서 연락드리겠습니다" 안내 표시.

## 배포 & 산출물

- 배포는 기존과 동일하게 GitHub Pages(main 브랜치 push 시 자동 반영), 빌드 과정 추가 없음.
- `firestore.rules`를 저장소에 포함해 코드로 관리.
- `docs/사용설명서.md`: 어드민 화면에서 이벤트/혜택/공지/사후관리 글 올리는 법, 상담 신청 확인하는 법을 텍스트+단계로 정리 (UI를 쉽게 만들되, 보조 문서도 함께 제공).

## 범위 밖 (이번 작업에서 하지 않음)

- 예약 시스템, 카카오맵 연동, SEO 작업, 반응형 모바일 최적화, 디자인 전면 재제작 — 계약서상 별도 협의/추가 비용 항목이며 이번 스펙 범위에 포함하지 않는다.
- 자동 발송 알림(문자/카카오톡/푸시) — 사후관리 안내는 정적 콘텐츠로만 제공.
- 다른 병원 대상 재사용/멀티테넌트 구조 — 지금은 고려하지 않고, 필요해지면 그때 리팩토링한다.
- 회원가입, 비밀번호 기반 고객 인증 — 고객 전용 페이지는 비공개 링크 방식으로만 접근 제한한다.
